## What the audit found

The Facebook card on `/dashboard/engagement` renders **"no insights available
yet"**. The previous review noted this and declined to call it the cause of any
rejection -- correctly, since all four reviewer notes are identical. What it did
not do was ask *why* the panel was empty.

It is empty because **the metric names are dead**:

```
page_impressions          -> (#100) The value must be a valid insights metric
page_impressions_unique   -> (#100) The value must be a valid insights metric
page_fans                 -> (#100) The value must be a valid insights metric
```

The same Page token, in the same request cycle, returns:

```
fan_count        21
followers_count  21
feed             2 posts, with likes.summary and comments.summary
```

`pages_read_engagement` works. Gituas asks for metrics Meta deleted.

Seven metrics survive: `page_post_engagements`, `page_follows` (= 21),
`page_daily_follows_unique`, `page_views_total`, `page_total_actions`,
`page_video_views`, `page_actions_post_reactions_total`. Only `page_follows`
is non-zero.

## Why this went unseen for three submissions

`src/app/dashboard/engagement/actions.ts:118`:

```ts
// Insights are best-effort: Meta withholds Page insights for small/new pages,
// so a failure here isn't actionable for the user -- the panel just shows its
// empty state. Don't surface it in the error banner.
const insightsRes = await fetchPageInsights(tenantId);
```

The comment asserts a cause -- "Meta withholds Page insights for small/new
pages" -- that is false here. The error was a code bug, and the code was written
to hide exactly this error. Three App Review rounds passed over it.

This is the same shape as the data-deletion callback fixed in `57ae951`:
a deliberate silence covering a real failure. Second occurrence of the pattern;
worth naming as a habit rather than an incident.

## Second finding

`src/app/dashboard/engagement/engagement-client.tsx:85`:

```ts
postGroups={data.facebook.posts.filter((p) => p.comments.length > 0)
```

Posts without comments are not rendered at all. The Page has 2+ posts and one
of them has comments, so the reviewer sees one post. `pages_read_engagement` is
defined by Meta as reading "content (posts, photos, videos, events) posted by
the Page" -- the headline capability is filtered out of its own demo.

## Architecture

```
                      dashboard/engagement/actions.ts
                                loadFacebook()
                                     |
     +--------------+----------------+---------------+----------------+
     v              v                v               v                v
  pageFields   fetchPageInsights  fetchPagePosts  fetchPageComments  fetchPageConversations
  (NEW)        (metrics fixed)    (now rendered)      x5
     |              |                |               |                |
     +--------------+----------------+---------------+----------------+
                                     |
                            loadFbCred()  <- non-expiring Page token
                                     |
                         graph.facebook.com/v25.0
```

The coupling that broke: the panel's contents depended entirely on Meta's
metric catalogue, which Meta prunes unilaterally. Followers now comes from a
Page node field, so the headline number survives the next pruning. Metrics
become decoration.

## Error and rescue map

| CODEPATH | FAILURE | BEFORE | AFTER |
|---|---|---|---|
| `fetchPageInsights` | invalid metric (#100) | swallowed silently | `console.error` + inline hint |
| `fetchPageInsights` | token / permission | swallowed silently | `console.error` + inline hint |
| page fields | request fails | n/a | falls through to `page_follows` |
| all follower sources fail | -- | n/a | empty state naming the reason |
| `fetchPagePosts` | any | error banner | unchanged |
| `fetchPageConversations` | any | error banner | unchanged |

The user-facing error banner is deliberately not used for insights: a red
banner on camera during a review recording is a direct cost. The failure
becomes visible in logs and as an inline hint instead.

## Edge cases

| Case | Handling |
|---|---|
| Page has zero posts | empty state, "nothing posted yet" |
| Post has no message (photo-only) | existing fallback to the literal "post" |
| More than 6 posts | bounded at 6 by `fetchPagePosts` |
| Every metric returns zero | hidden; followers still renders from the field |
| `fan_count` absent | `followers_count`, then `page_follows` |
| Page has 0 followers | renders `0` -- honest, and not an empty panel |

## Deployment

about two minutes. Old and new code can run concurrently without conflict.

**Gate before recording:** the Facebook card must render `21` followers and at
least one post. If it does not, recording does not start.
